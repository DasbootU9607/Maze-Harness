# Deriving a new design

Choose the complete exit, final working shield and required input stance first. Decide whether the preceding route can reach an already available shield (BxB branch) or must first transport and place that shield, then create another approach (BxC branch). Where tools travel together, derive the actual contact line and a useful shared destination. At that destination, ensure the player can separate roles without losing the future contact or its own return stance. Make a retreat serve a concrete reapproach, then replay the prepared handoff and final safe release. Choose geometry and direction order autonomously; neither source fixes a block count or stage count. A compact request may isolate one handoff. A composed design connects preparation, executable contact and subsequent work; an unused box or repeated straight push is not a stage.

Select the functional branch using [reference-catalog.json](reference-catalog.json) and [difficulty.md](difficulty.md), not a solved silhouette. Begin with [design-template.json](design-template.json), whose geometry/events/routes remain empty. Record the current mechanism-logic SHA256 before choosing layout. Map each relation to actual members, contact directions, clear-ground stances and a full goal.

For a prepared handoff, test the final next action from an ordinary reachable branch with and without the intended preparation. Preserve player/helper approach conditions where practical; a decorative event count is not proof. Whole-goal bypasses and global necessity need separate compatible searches. If the goal is doorway access, accept a genuine free door slot; do not add a central-cell condition without a functional reason.

The included helper verifies unchanged official references only. It is not an authored-map builder or a transfer certificate. A requested new map needs its own build, ordinary full-goal replay and causal controls.
